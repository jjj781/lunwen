## How to run

Create or reuse an env that can import the packages above. On a 4090D, install a PyTorch build that supports Ada (CUDA 11.8 or 12.x). Then, from the repo:

```powershell
python test_IVF.py
python train.py --batch_size 4 --tag base
python train.py --batch_size 4 --decomp_cc channel --tag cc
python train.py --batch_size 4 --residual max --tag res
python train.py --batch_size 4 --h5_path data/MSRS_train_imgsize_128_stride_100.h5 --augment --tag data
python train.py --batch_size 4 --h5_path data/MSRS_train_imgsize_128_stride_100.h5 --augment --decomp_cc channel --residual max --tag all
python test_IVF.py --ckpt models/CDDFuse_<tag>_<timestamp>.pth
```

Run one training at a time. Checkpoints land in `models/` and include the CLI args. `test_IVF.py` overwrites `test_result/`, so record the printed metrics before the next test.

## Speed facts already measured

Do not repeat these experiments.

- A4500, batch 4, phase-I step about 0.31 s, peak 10.6 GB. About two-thirds of that is backward. One stride-200 run (120 epochs, 6487 patches) is about 15.5 hours.
- Updating every 8 images with micro-batch 4 does not shorten the epoch. Every image is still forwarded and differentiated once. It only matches an effective batch of 8.
- True batch 8 peaked at 21 GB and took about 2.7 s per step on the 20 GB A4500 because it spilled. Do not use batch 8 on a 20 GB card.
- Opening the h5 file once, or removing `DataParallel`, does not save hours.
- 4090D estimate for this same batch-4 job: about 2 to 2.5 times faster, so about 6 to 8 hours per stride-200 run. Stride-100 runs have about 4 times the patches. Five runs on a 4090D are still on the order of two days. 24 GB may fit batch 8; that was not measured, and it is not required to match the current plan.
